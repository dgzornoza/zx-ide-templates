# z88dk C Coding Conventions

## Canonical name vs. decorated suffix — never call `_callee` / `_fastcall` from C

z88dk headers (under `include/_DEVELOPMENT/proto/*.h`, expanded via the m4
macro in `include/_DEVELOPMENT/__link__.m4`) declare every library function
**twice** plus one preprocessor redirect:

```c
// Generated by __DPROTO for SDCC, taking the >6-arg branch:
extern unsigned char dzx0_standard       (void *src, void *dst) __SMALLC;
extern unsigned char dzx0_standard_callee(void *src, void *dst) __SMALLC __z88dk_callee;
#define dzx0_standard(a, b) dzx0_standard_callee(a, b)
```

The macro is what makes the system work:

- **In C source**: call the canonical name (`dzx0_standard(src, dst)`).
- **At preprocessing**: the macro rewrites the call to the decorated variant
  (`dzx0_standard_callee(src, dst)`).
- **At link time**: the linker pulls in the `_callee` wrapper that matches the
  pragma-active calling convention (here `__z88dk_callee` because the project
  uses `sdcc_iy` clib).

**Rule**: never write `_callee` (or `_fastcall`) in the call site. Always
use the canonical name. The call site stays portable across the two calling
conventions z88dk exposes for every library function.

```c
// ✅ Correct — canonical name, the macro picks the variant
dzx0_standard(hud_tiles_compressed, (void *)SYS_SCREEN_PIXEL_ADDR);

// ❌ Wrong — bypasses the macro, locks the project to callee ABI, breaks
//   if a future pragma flips the convention to fastcall
dzx0_standard_callee(hud_tiles_compressed, (void *)SYS_SCREEN_PIXEL_ADDR);
```

Same rule applies to every z88dk library function that has both a plain and
a `_callee` / `_fastcall` form: `sp1_TileEntry`, `sp1_PrintAtInv`,
`fill_attr_rect`, etc. Use the canonical name; trust the macro.

## Why this matters

1. **Convention changes become free.** If the project later switches its
   clib default convention, code that uses the canonical name compiles and
   links unchanged. Code that hardcodes `_callee` breaks.
2. **One source of truth for ABI.** The wrapper's job is to bridge
   `__z88dk_callee` arg-passing and the callee's native convention. The
   macro is what tells the C compiler to emit a callee-ABI call. Bypassing
   either half is a foot-gun.
3. **Source-level debugging is readable.** A debugger that maps source
   lines to the first instruction of the call sees a canonical `call <func>`
   rather than a call whose name already encodes the ABI.
